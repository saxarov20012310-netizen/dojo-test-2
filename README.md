# Услуги и форма записи — тестовое задание

Вёрстка двух блоков по макету из Figma: слайдер услуг и форма записи на консультацию.

**Демо:** https://saxarov20012310-netizen.github.io/dojo-test-2/

## Что сделано

**Слайдер услуг**
- 9 карточек, лента медленно и бесконечно едет влево. Движение через `transform` с дробными пикселями — плавно на любой скорости (прокрутка через `scrollLeft` округляется до целых пикселей и на малой скорости дёргается).
- При наведении лента плавно тормозит и так же плавно разгоняется, без рывков. Её можно тянуть мышью и пальцем (с инерцией после броска) и листать тачпадом или колесом с Shift (`js/slider.js`).
- Для бесконечности карточки продублированы, копия скрыта от скринридеров и клавиатуры. Карточка, получившая фокус с клавиатуры, выезжает в начало ленты. При `prefers-reduced-motion` автопрокрутка выключена.
- Вырез под кнопки в карточке — контур из макета в `clip-path: path()`, фото отдельно от формы карточки.
- Кнопка «Консультация» подставляет услугу в скрытое поле формы и переводит фокус в поле ФИО.
- На мобильном — маленькие карточки 154 px, кнопки под фото, как в мобильном макете.

**Форма записи**
- Фигура со скосами и скруглениями адаптивная: контур не растягивается как картинка, а пересчитывается под фактический размер блока (`js/consult-shape.js`). Каждая точка привязана к своему краю, поэтому на любой промежуточной ширине скосы и скругления сохраняют геометрию из макета.
- До 1023 px форма перестраивается в колонку с отдельным контуром из мобильного макета.
- Фото специалиста подгружается динамически: `js/specialist.js` берёт `{ photo, alt }` из `data/specialist.json` — в проекте этот файл заменяется ответом API админки. Ожидается PNG/WebP с прозрачным фоном; если запрос не удался, остаётся фото по умолчанию из разметки.
- Телефон сразу начинается с `+7` и форматируется при вводе: `+7 (999) 123-45-67`. Номер, вставленный как `8 999…`, приводится к `+7`.
- Простая проверка полей и сообщение об успешной отправке (`js/form.js`), без бэкенда.

## Точность

Сверял с макетом численно: скриншоты вёрстки в размерах макета (1440×936 и 390×1057, лента в начальном положении) вычитал из экспорта Figma.

- Десктоп: средняя разница 2,2 из 255 на пиксель, все строки текста — ±1 px.
- Мобильный: 2,9 из 255, высота формы 789 px — как в макете.

Особенности макета, которые повторены намеренно:
- у первой карточки градиент темнее и холоднее (`#1B2338`), а заголовок стоит на 5 px правее и на 2 px выше остальных — модификатор `service-card--cool`;
- на картинку «Протезирование» в макете наложен фильтр обесцвечивания — применён к самой картинке;
- межстрочные интервалы заданы явно: браузерный `line-height: normal` у Montserrat округляется иначе, чем «Auto» в Figma.

Единственное сознательное отличие: форма занимает всю ширину контейнера (1200 px), в макете — 1199 px.

## Стек и структура

HTML, CSS (BEM), немного JavaScript, без сборки и фреймворков. Шрифт Montserrat — Google Fonts.

```
index.html
css/style.css          стили, адаптив: до 1023 px и до 767 px
js/consult-shape.js    контур формы под текущий размер
js/slider.js           лента: автопрокрутка, перетаскивание, тачпад
js/specialist.js       фото специалиста «из админки»
js/form.js             маска телефона, подстановка услуги, проверка формы
data/specialist.json   имитация ответа админки
img/                   обложки услуг (WebP + JPG, 2x), фото, фон формы, иконки
```

Запуск: любой статический сервер (фото специалиста грузится через `fetch`, с `file://` не заработает):

```
python -m http.server 8000
```

Вёрстку делал с помощью Claude Code (Anthropic), макет читал через Figma MCP. Картинки карточек собраны из исходных фото макета с тем же кадрированием, что в Figma. Соответствие макету проверял скриптом сравнения скриншотов и вручную в браузере на ширинах 1440, 1100, 900, 600 и 390.
